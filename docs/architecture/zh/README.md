# Codara Agent Runtime 架构教程

> 这套教程讲的不是"怎么接一个模型"，而是"怎么把模型放进一个能长期工作的系统里"。

Agent Runtime 最容易被误解的地方，是大家总以为难点在模型。
真正的难点其实在环境：工具怎么接、上下文怎么管、状态怎么存、多个 Agent 怎么协作、系统中断以后怎么继续。

所以这套教程的主线很简单：

- Agent 是模型
- Harness 是环境
- 架构的价值，在于把模型从一次性回答器，变成可扩展、可恢复、可协作的执行系统

## 怎么理解这 16 章

它们不是并列知识点，而是一条很清楚的生长链。

**第一部分（第1-11章）：Agent Core**
- 第1-4章：单 Agent 的成立条件（循环、上下文、工具）
- 第5-6章：单 Agent 的稳定性（知识、规划）
- 第7-11章：从单体到协作网络（子 Agent、任务、团队、协议、自治）

**第二部分（第12-16章）：Harness Layer**
- 第12-13章：定时机制（Heartbeat 轮询 + Cron 调度）
- 第14章：多渠道接入（IM Channels）
- 第15章：长期记忆（Memory）
- 第16章：个性化（Soul）

如果把整套教程压成一句话，它讲的是：

**一个模型，如何在不改变推理本质的前提下，被逐步包裹成一个可扩展、可恢复、可协作、可常驻的 Harness。**

---

## 五条总原则

### 1. 主循环尽量不变

新增能力应该尽量外挂，而不是不断重写核心执行语义。

### 2. 静态和动态必须分开

身份、规则、工具定义应尽量稳定；历史、结果、进展天然会增长。

### 3. 工具是正式扩展面

能力增长应该主要发生在工具层，而不是侵入循环层。

### 4. 磁盘是真相来源

一旦涉及跨轮次任务、长时执行、多 Agent 协作，内存就不再够用。

### 5. 协作靠消息，不靠共享脑子

每个 Agent 都应该有自己的上下文和生命周期，彼此通过消息和协议协作。

---

## 这套教程适合谁

它适合两类人：

- 想系统理解 Agent Runtime 的工程师
- 面试里需要把多 Agent 架构讲清楚的人

所以这份文档会刻意少写代码，多写原理、边界和因果链。
代码会变，机制不会轻易变。

---

## 面试里怎么一句话概括

可以直接说：

**Agent Runtime 的核心，不是模型本身，而是围绕模型建立执行环境；先用循环、上下文和工具让单 Agent 成立，再用知识、规划、任务、协议和自治把它扩展成一个长期运行的协作系统；最后通过 Heartbeat、Cron、IM Channels、Memory 和 Soul 让它从临时工具变成常驻助手。**

---

## 阅读建议

第一次读，按顺序走，不要跳。
准备面试时，每章至少抓住三件事：

- 这一章解决什么问题
- 为什么必须这样设计
- 如果没有这一层，系统会坏在哪里

把这三件事讲顺，说明你真的理解了。
